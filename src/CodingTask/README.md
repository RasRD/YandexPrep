# Задача 2 — SiteCrawler

## Цель

Реализовать сервис построения карты сайта и написать unit-тесты.

Базовая версия рассчитана на **60 минут вместе с тестами**.
Усложнения выполняются отдельно после проверки базовой реализации.

Стек: C# / .NET, стандартная библиотека, xUnit.

## Условие

Есть готовый источник, который асинхронно возвращает ссылки со страницы.

Нужно обойти сайт, начиная со стартового адреса, и вернуть карту:
для каждой обработанной страницы — ссылки на другие страницы либо ошибка загрузки.

Реальные HTTP-запросы и HTML-парсер реализовывать не нужно.

## Контракты

```csharp
public interface IPageSource
{
    Task<IReadOnlyList<Uri>> GetLinksAsync(Uri page);
}

public sealed record PageResult(
    IReadOnlyList<Uri> Links,
    Exception? Error);

public interface ISiteCrawler
{
    Task<IReadOnlyDictionary<Uri, PageResult>> CrawlAsync(Uri startPage);
}
```

Класс реализации — `SiteCrawler`.

Зависимость `IPageSource` передаётся через конструктор.
Внутреннюю структуру решения нужно спроектировать самостоятельно.

## Требования базовой версии

### 1. Обход сайта

- Обработать стартовую страницу и все страницы, достижимые от неё по ссылкам внутри сайта.
- В базовой версии обращения к источнику выполняются последовательно:
  одновременно выполняется не более одного обращения.
- Порядок посещения страниц произвольный.

### 2. Граница сайта

- Принадлежность сайту определяется по `Host` стартового URI без учёта регистра.
- Схема и порт для этой проверки не учитываются.
- Страницы других сайтов не загружаются, ссылки на них не включаются в результат.

### 3. Повторяющиеся адреса

- Каждый адрес запрашивается максимум один раз за один вызов `CrawlAsync`.
- Это правило действует также для неуспешных загрузок.
- Возможны повторяющиеся ссылки, ссылки на себя и циклы между страницами.
- Повторных попыток загрузки нет.

### 4. Результат

- В результате есть запись для каждой страницы, которую пытались загрузить,
  включая стартовую.
- Порядок записей словаря произвольный.
- При успешной загрузке `Error == null`.
- В `Links` остаются только ссылки внутри сайта.
- Повторы в `Links` удаляются с сохранением порядка первого появления.
- Ссылки на себя и уже посещённые страницы остаются в `Links`.

### 5. Ошибки загрузки

Если источник выбросил обычное исключение при вызове метода или ожидании задачи:

- сохранить исходный объект исключения в `Error`;
- записать пустой список в `Links`;
- продолжить обработку остальных обнаруженных страниц.

Ошибка отдельной страницы не должна прерывать весь обход.

### 6. Валидация

- `pageSource == null` в конструкторе — `ArgumentNullException`.
- `startPage == null` — `ArgumentNullException`.
- Относительный стартовый URI — `ArgumentException`.
- Стартовый URI со схемой, отличной от HTTP/HTTPS, — `ArgumentException`.
- При неверном стартовом URI источник не вызывается.

### 7. Завершение

Метод возвращает результат только после завершения обработки
всех обнаруженных страниц.

После возврата результата не должно оставаться незавершённых обращений
к источнику, запущенных этим обходом.

## Допущения и ограничения

- Источник возвращает только валидные абсолютные HTTP/HTTPS URI.
- Источник не возвращает `null` вместо списка или его элементов.
- Адреса уже нормализованы; схема и имя хоста приведены к нижнему регистру.
- Адреса не содержат query и fragment. Обработка редиректов не требуется.
- URI с одинаковым `AbsoluteUri` обозначают одну страницу.
  Сравнение адресов — порядковое, с учётом регистра.
- Граф конечный, внутри сайта достижимо не более 1000 страниц.
- Все данные помещаются в память.
- В тестах используется подставной `IPageSource`.
- Одновременные вызовы `CrawlAsync` на одном экземпляре
  в базовой версии не проверяются.
- Отмена, таймауты и повторные попытки загрузки вне базовой версии.

## Пример

Стартовый адрес: `https://shop.test/a`.

В таблицах `/a`, `/b`, `/c` обозначают полные адреса на `https://shop.test`.

Источник возвращает:

| Страница | Ответ источника |
| --- | --- |
| `/a` | `/b`, `/b`, `/c`, `https://other.test/x` |
| `/b` | `/a`, `/c` |
| `/c` | Исключение `ex` |

Ожидаемый результат:

| Страница | Links | Error |
| --- | --- | --- |
| `/a` | `/b`, `/c` | `null` |
| `/b` | `/a`, `/c` | `null` |
| `/c` | пустой список | тот же объект `ex` |

Каждая из трёх страниц запрашивается один раз.
Страница `https://other.test/x` не запрашивается.

## Тестирование

Самостоятельно выбрать и написать компактный набор xUnit-тестов,
проверяющих контракт и граничные случаи.

Для каждого теста нужно уметь объяснить:

- какое поведение он проверяет;
- какую ошибку реализации способен обнаружить.

## Критерии проверки

- Соблюдение контракта.
- Корректное завершение обхода.
- Обоснованный выбор структур данных.
- Понятный и работающий код.
- Корректная обработка ошибок.
- Содержательные и запускаемые тесты.
- Способность объяснить решение и его сложность.

## Усложнение 1 — ограниченный параллельный обход

Выполняется отдельно после проверки базовой версии.

Добавить `maxConcurrency` в конструктор:

- Значение должно быть положительным.
  Иначе — `ArgumentOutOfRangeException`.
- Одновременно выполняется не более `maxConcurrency`
  незавершённых обращений к источнику в рамках одного обхода.
- При наличии независимых страниц должна использоваться
  доступная параллельность.
- Если разные загрузки обнаружили один адрес,
  он всё равно запрашивается максимум один раз.
- Все страницы, обнаруженные во время загрузок,
  обрабатываются до возврата результата.
- Источник поддерживает конкурентные вызовы.
- Лимит действует на один `CrawlAsync`.
  Общий лимит между несколькими обходами не требуется.

Остальные правила базовой версии сохраняются.

Добавить тесты на параллельность и соблюдение лимита.
Результат тестов не должен зависеть от случайных задержек.
Ограниченный таймаут допустим как защита от зависания теста.

## Усложнение 2 — отмена обхода

Выполняется отдельно после проверки параллельной версии.

Добавить `CancellationToken` в оба асинхронных контракта:

- Передавать токен источнику.
- При заранее отменённом токене и корректном входе не начинать загрузки.
- После обнаружения отмены не начинать новые загрузки.
- Завершать обход через `OperationCanceledException`.
- Отмену обхода не записывать как ошибку отдельной страницы.
- Перед завершением обхода дождаться завершения уже запущенных обращений.

Для этой версии источник гарантированно реагирует на переданный токен
и завершает запросы.

Между фактической отменой и её обнаружением допускается гонка.
Обычные ошибки страниц сохраняют прежнее поведение.

Точные сигнатуры согласуются перед реализацией этого усложнения.
